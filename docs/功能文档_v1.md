## 一、功能模块概述

NimbusDrive 是一个企业级分布式文件存储系统，支持多平台访问。系统架构基于 Go（后端） + React（前端） + React Native（移动端），采用 RESTful API 和 WebDAV 协议，支持多种文件类型，具备高性能上传下载、安全分享、精细配额管理、文件列表管理能力。

系统核心功能模块划分：

1.  **文件管理模块**
2.  **用户管理模块**
3.  **配额管理模块**
4.  **分享管理模块**
5.  **文件列表管理模块**

本文档聚焦于前五个核心场景：上传、下载、分享、配额、文件列表，是《实现方案》v1 的详细解读与功能说明。

## 二、核心场景与功能详述

### 2.1 上传功能（文件管理模块）

#### 2.1.1 功能描述

用户可通过 Web 端或移动端，上传任意大小的文件（单文件最大 10GB），文件名长度不超过 255 字符，仅允许字母、数字、下划线。支持断点续传、秒传、分块上传、进度可视化。系统默认支持多种文件类型，如视频（mp4）、文档（docx）、图片（jpeg）、压缩包（zip）等。

#### 2.1.2 功能流程

1.  **用户选择文件**：用户在前端界面选择一个 500MB 的视频文件 `my_video.mp4`。
2.  **前端参数校验**：前端校验文件名 `my_video.mp4`、文件类型 `video/mp4`、文件大小 500MB、文件内容（无敏感词）。若任何一项不满足要求，提示用户并阻止上传。
3.  **后端参数校验**：后端接收文件，二次校验文件名、文件类型、文件大小、内容，确保与前端一致。
4.  **文件哈希计算**：服务端计算文件 MD5/SHA256 哈希值，用于秒传校验。
5.  **哈希值查询**：服务端查询 `file_hashes` 表，如果哈希值已存在，则执行秒传；否则，执行上传。
6.  **分块上传**：文件大小超过 500MB 时，分块上传（4MB），支持断点续传。分块上传采用多线程并发，提高上传效率。
7.  **分块合并**：上传完成后，服务端合并分块，生成完整文件。
8.  **完整性校验**：服务端校验文件完整性，确保上传成功。
9.  **元数据写入**：服务端写入文件元数据到 `files` 表，包括文件名、大小、类型、创建时间、更新时间、权限、存储路径、哈希值。
10. **文件内容写入**：服务端将完整文件写入 MinIO 对象存储系统，存储路径为 `user/{user_id}/file/{file_id}`。
11. **文件哈希写入**：服务端将文件哈希值写入 `file_hashes` 表，建立文件哈希与存储路径的映射关系。
12. **日志记录**：服务端记录上传日志，包含上传耗时、文件大小、分块数、成功率。
13. **前端反馈**：服务端返回成功响应，前端显示上传成功（文件名、大小、类型、创建时间、更新时间、存储路径、哈希值）。
14. **文件列表更新**：前端更新文件列表，展示新上传的文件。

#### 2.1.3 上传参数

| 参数 | 描述 | 限制 |
|------|------|------|
| file | 文件内容 | 必填，最大 10GB |
| parent_id | 父文件夹ID | 可选，若为文件夹则只返回该文件夹的子文件 |
| name | 文件名 | 必填，长度 1~255 字符，仅允许字母、数字、下划线 |
| storage | 存储名称 | 可选，如 `private`、`public` |
| storage_path | 存储路径 | 可选，如 `/private/user/123` |

#### 2.1.4 上传边界条件

1.  **文件大小边界**：文件大小 ≤ 10GB，否则上传失败。
2.  **文件名边界**：文件名长度 1~255 字符，仅允许字母、数字、下划线，否则上传失败。
3.  **文件类型边界**：文件类型符合允许的类型（如 `video/mp4`），否则上传失败。
4.  **文件内容边界**：文件内容不包含敏感词（如 " copyrighted"），否则上传失败。
5.  **分块上传边界**：文件大小超过 500MB 时，分块上传（4MB），支持断点续传。
6.  **秒传边界**：文件哈希值查询 `file_hashes` 表，命中则秒传，未命中则上传。
7.  **上传成功边界**：上传成功 → 服务端返回成功响应，客户端显示上传成功。
8.  **上传失败边界**：上传失败 → 服务端返回 500 错误，记录错误日志。
9.  **文件权限边界**：用户无权限上传文件 → 403 错误，提示用户无权限。

#### 2.1.5 上传异常处理

-  **网络中断异常**：网络中断 → 重试上传（从断点位置继续）。
-  **服务器异常**：服务器错误 → 返回 500 错误，记录错误日志。
-  **文件名非法异常**：文件名非法 → 返回 400 错误，提示文件名格式错误。
-  **文件大小超限异常**：文件大小超限 → 返回 400 错误，提示文件过大。
-  **文件类型不支持异常**：文件类型不支持 → 返回 400 错误，提示文件类型不支持。
-  **文件内容包含敏感词异常**：文件内容包含敏感词 → 返回 400 错误，提示内容违规。
-  **文件权限不足异常**：文件权限不足 → 返回 403 错误，提示用户无权限。

#### 2.1.6 上传业务规则

-  **上传文件** → 服务端返回 `id`、`storage_path`、`hash_sha256`、`size`、`mime_type`、`created_at`、`updated_at`。
-  **上传成功** → 客户端显示上传成功（文件名、文件大小、文件类型、文件创建时间、文件更新时间）。
-  **上传失败** → 客户端提示上传失败。
-  **秒传** → 客户端提示秒传成功。
-  **上传日志** → 服务端记录上传耗时、文件大小、分块数、成功率。
-  **上传进度** → 客户端在 UI 显示上传进度、下载速度、预计剩余时间。
-  **文件列表更新** → 客户端更新文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间）。

### 2.2 下载功能（文件管理模块）

#### 2.2.1 功能描述

用户可通过 Web 端或移动端，根据文件 ID 或文件名，下载文件。支持 Range 请求（多线程下载）、断点续传、文件校验。系统默认支持多种文件类型，如视频（mp4）、文档（docx）、图片（jpeg）、压缩包（zip）等。

#### 2.2.2 功能流程

1.  **用户发起下载**：用户在前端界面点击下载按钮，选择一个 500MB 的视频文件 `my_video.mp4`。
2.  **前端参数校验**：前端校验文件 ID 或文件名，确保文件存在、权限足够。若文件不存在或权限不足，提示用户并阻止下载。
3.  **后端参数校验**：后端接收下载请求，二次校验文件 ID、文件名、权限，确保与前端一致。
4.  **文件大小查询**：服务端查询文件大小，确保文件存在。
5.  **分块数计算**：服务端计算分块数（文件大小 / 块大小），支持断点续传。
6.  **Range 请求发起**：服务端发起 Range 请求（多线程），获取文件内容。
7.  **文件内容合并**：服务端合并下载的数据，生成完整文件。
8.  **完整性校验**：服务端校验文件完整性，确保下载成功。
9.  **文件内容返回**：服务端返回文件内容（Auto-Detect 二进制）。
10. **日志记录**：服务端记录下载日志，包含下载耗时、文件大小、分块数、成功率。
11. **前端反馈**：服务端返回成功响应，前端显示下载成功（文件名、文件大小、下载速度、预计剩余时间）。
12. **文件播放器打开**：前端打开文件播放器播放视频。

#### 2.2.3 下载参数

| 参数 | 描述 | 限制 |
|------|------|------|
| id | 文件 ID | 必填，文件存在 |
| range | Range 请求范围 | 可选，如 `bytes=0-499999999` |

#### 2.2.4 下载边界条件

1.  **文件大小边界**：文件大小 ≤ 10GB，否则下载失败。
2.  **Range 请求边界**：Range 请求覆盖文件范围（如 `bytes=0-499999999`），支持断点续传。
3.  **并发下载边界**：5 个并发线程下载（最大并发下载数为 5）。
4.  **文件校验边界**：下载完成后校验 MD5/SHA256（可选）。
5.  **文件状态边界**：文件为正常状态（非删除、非隐藏），权限足够。
6.  **弱网环境边界**：用户在 4G 环境下下载，速度降低（大文件场景下，WiFi 下用 4MB、4G 下用 1MB）。
7.  **安全边界**：文件内容为合法内容，无敏感词（如 " copyrighted"）。
8.  **文件效率边界**：并发下载，降低下载延迟。

#### 2.2.5 下载异常处理

-  **服务器异常**：服务器错误 → 返回 500 错误，记录错误日志。
-  **文件不存在异常**：文件不存在 → 返回 404 错误，提示文件不存在。
-  **文件权限不足异常**：文件权限不足 → 返回 403 错误，提示用户无权限。
-  **文件已删除异常**：文件已删除 → 返回 404 错误，提示文件已删除。
-  **文件类型不支持异常**：文件类型不支持 → 返回 400 错误，提示文件类型不支持。
-  **文件内容包含敏感词异常**：文件内容包含敏感词 → 返回 400 错误，提示内容违规。

#### 2.2.6 下载业务规则

-  **下载文件** → 服务端返回 `storage_path`、`hash_sha256` → 返回文件内容。
-  **下载成功** → 客户端显示下载完成（文件名、文件大小、下载速度、预计剩余时间）。
-  **下载失败** → 客户端提示下载失败。
-  **下载日志** → 服务端记录下载耗时、文件大小、分块数、成功率。
-  **下载进度** → 客户端在 UI 显示下载进度、下载速度、预计剩余时间。
-  **文件播放器** → 客户端打开文件播放器播放视频。

### 2.3 分享功能（分享管理模块）

#### 2.3.1 功能描述

用户可通过 Web 端或移动端，选择一个文件，生成分享链接，支持密码保护、过期时间、访问次数控制。用户分享链接给朋友，朋友访问链接时输入密码，验证成功后下载文件。

#### 2.3.2 功能流程

1.  **用户选择文件**：用户在前端界面选择一个 500MB 的视频文件 `my_video.mp4`。
2.  **前端参数校验**：前端校验文件 ID、文件名、文件权限，确保文件存在、权限足够。若文件不存在或权限不足，提示用户并阻止分享。
3.  **后端参数校验**：后端接收分享请求，二次校验文件 ID、文件名、权限，确保与前端一致。
4.  **短 ID 生成**：服务端生成 8 位随机短 ID，防枚举。
5.  **密码生成**：服务端生成强密码（8 位以上）。
6.  **过期时间生成**：服务端生成过期时间（7 天）。
7.  **访问次数生成**：服务端生成访问次数限制（100 次）。
8.  **分享信息写入**：服务端将分享信息写入 Redis（key: `share:{id}`，value: `{userId, fileId, expireTime, password}`）。
9.  **分享链接返回**：服务端返回分享链接 `https://yourdomain.com/share/{id}`。
10. **前端反馈**：服务端返回成功响应，前端显示分享链接（https://yourdomain.com/share/{id}）。
11. **分享访问**：朋友访问分享链接，输入密码，验证成功后下载文件。
12. **访问日志**：服务端记录每次访问（用户ID、文件ID、访问时间、IP地址）。

#### 2.3.3 分享参数

| 参数 | 描述 | 限制 |
|------|------|------|
| id | 文件 ID | 必填，文件存在 |
| password | 分享密码 | 可选，强密码（≥8位） |
| expire_time | 过期时间 | 可选，格式：2026-08-23 00:00:00 |
| max_access_count | 最大访问次数 | 可选，整数 |

#### 2.3.4 分享边界条件

1.  **分享链接边界**：短 ID 由 8 位随机生成，防枚举。
2.  **密码保护边界**：密码 `myPassword123` 强度 ≥ 8 个字符。
3.  **过期时间边界**：7 天，过期时间在 2026-08-23 00:00:00。
4.  **访问次数边界**：访问次数限制为 100 次。
5.  **分享访问日志边界**：记录每次访问，包括访问时间、IP地址、用户ID。
6.  **分享取消边界**：用户点击取消分享，链接失效。
7.  **分享统计边界**：记录分享链接访问次数，如果超过 100 次，访问失败，提示次数用完。
8.  **安全边界**：文件内容为合法内容，无敏感词（如 " copyrighted"）。

#### 2.3.5 分享异常处理

-  **服务器异常**：服务器错误 → 返回 500 错误，记录错误日志。
-  **文件不存在异常**：文件不存在 → 返回 404 错误，提示文件不存在。
-  **文件权限不足异常**：文件权限不足 → 返回 403 错误，提示用户无权限。
-  **分享链接过期异常**：分享链接过期 → 返回 403 错误，提示链接已过期。
-  **分享访问次数用完异常**：分享访问次数用完 → 返回 403 错误，提示次数用完。
-  **分享链接被取消异常**：分享链接被取消 → 返回 403 错误，提示链接已被取消。
-  **文件内容包含敏感词异常**：文件内容包含敏感词 → 返回 400 错误，提示内容违规。

#### 2.3.6 分享业务规则

-  **分享文件** → 服务端返回 `短 ID`、`分享链接` → 返回分享成功。
-  **分享成功** → 客户端显示分享链接（https://yourdomain.com/share/{id}）。
-  **分享失败** → 客户端提示分享失败。
-  **分享访问日志** → 服务端记录每次访问（用户ID、文件ID、访问时间、IP地址）。
-  **分享统计** → 服务端记录分享链接访问次数，如果超过 100 次，访问失败，提示次数用完。
-  **分享链接过期或密码错误** → 服务端返回 403 错误，提示链接已过期或密码错误。
-  **分享链接被取消** → 服务端返回 403 错误，提示链接已被取消。

### 2.4 配额管理功能（配额管理模块）

#### 2.4.1 功能描述

用户初始配额 1GB，上传文件会自动更新用户配额，提示剩余空间。用户在管理端查看配额使用情况，包含已用空间、剩余空间、配额使用率、配额过期时间（每月 1 号重置）。

#### 2.4.2 功能流程

1.  **用户上传文件**：用户上传一个 500MB 的视频文件，系统自动更新用户配额。
2.  **配额更新**：服务端更新用户配额（已用空间 + 文件大小）。
3.  **配额使用率计算**：服务端计算配额使用率（已用空间 / 总空间配额）。
4.  **剩余空间计算**：服务端计算剩余空间（总空间配额 - 已用空间）。
5.  **配额使用情况返回**：服务端返回配额使用情况（`used_storage`, `storage_quota`, `quota_usage_percent`）。
6.  **前端反馈**：服务端返回成功响应，前端显示配额使用情况（已用空间、剩余空间、配额使用率）。
7.  **配额不足提示**：当配额使用率 ≥ 95% 时，提示配额不足。
8.  **配额重置**：每月 1 号重置配额。

#### 2.4.3 配额参数

| 参数 | 描述 | 限制 |
|------|------|------|
| storage_quota | 总空间配额 | 可选，单位：字节 |
| used_storage | 已用空间 | 可选，单位：字节 |
| quota_usage_percent | 配额使用率 | 可选，0~100% |
| storage_enabled | 是否启用配额 | 可选，布尔值 |
| quota_exceeded_message | 超配额提示消息 | 可选，字符串 |

#### 2.4.4 配额边界条件

1.  **配额使用率边界**：用户上传文件后，配额使用率 = 已用空间 / 总空间配额。
2.  **配额超限边界**：用户上传文件时，如果使用超过配额，上传失败。
3.  **配额重置边界**：每月 1 号重置配额。
4.  **配额审计边界**：记录用户配额使用情况（每月日志）。
5.  **配额触发边界**：当配额使用率 ≥ 95% 时触发提醒。
6.  **配额类型边界**：配额类型为字节，1GB = 1024*1024*1024 字节。
7.  **配额单位边界**：配额单位为字节，10GB = 10*1024*1024*1024 字节。
8.  **配额级联边界**：用户有多个子账号，配额共享。

#### 2.4.5 配额异常处理

-  **配额超限异常**：配额超限 → 返回 400 错误，提示配额不足。
-  **用户配额为 0 异常**：用户配额为 0 → 返回 403 错误，提示用户配额已用完。
-  **配额重置时间未到异常**：配额重置时间未到 → 返回 403 错误，提示配额未重置。
-  **用户配额已过期异常**：用户配额已过期 → 返回 403 错误，提示配额已过期。

#### 2.4.6 配额业务规则

-  **上传文件** → 服务端更新用户配额（已用空间 + 文件大小）。
-  **配额使用** → 服务端计算配额使用率（已用空间 / 总空间配额）。
-  **配额不足** → 服务端返回 400 错误，提示配额不足。
-  **配额重置** → 服务端每月 1 号重置配额。
-  **配额审计** → 服务端记录用户配额使用情况（每月日志）。
-  **配额触发** → 当配额使用率 ≥ 95% 时，服务端触发提醒。
-  **配额使用率** → 服务端返回配额使用率（已用空间 / 总空间配额）。

### 2.5 文件列表管理功能（文件管理模块）

#### 2.5.1 功能描述

用户在管理端查看文件列表，支持文件名、文件大小、文件类型、文件状态、文件权限、文件存储路径、文件哈希值筛选。支持分页、排序、模糊搜索。默认每页 20 个文件，按创建时间倒序排列。

#### 2.5.2 功能流程

1.  **用户发起查询**：用户在前端界面输入筛选条件，如文件名包含 `video`，文件大小 > 100MB，文件类型为 `video/mp4`，排序方式为 `created_at desc`，每页显示 20 个文件，当前页为第 1 页。
2.  **前端参数校验**：前端校验筛选条件（文件名、文件大小、文件类型、文件状态、文件权限、文件存储路径、文件哈希值），确保查询条件合法。
3.  **后端参数校验**：后端接收查询请求，二次校验筛选条件，确保与前端一致。
4.  **文件列表查询**：服务端查询 `files` 表（sqlx），根据筛选条件返回文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值）。
5.  **分页处理**：服务端分页（每页 20 个文件），按排序方式排序。
6.  **返回文件列表**：服务端返回文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值）。
7.  **返回分页信息**：服务端返回分页信息（当前页、总页数、总记录数、是否有下一页、是否有上一页）。
8.  **前端反馈**：服务端返回成功响应，前端显示文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值），并显示分页信息（当前页、总页数、总记录数、是否有下一页、是否有上一页）。

#### 2.5.3 文件列表参数

| 参数 | 描述 | 限制 |
|------|------|------|
| page | 页码 | 可选，默认 1 |
| page_size | 每页大小 | 可选，默认 20 |
| sort_by | 排序字段 | 可选，`created_at, updated_at, name` |
| sort_direction | 排序方向 | 可选，`asc, desc` |
| parent_id | 父文件夹ID | 可选，若为文件夹则只返回该文件夹的子文件 |
| search | 搜索关键词 | 可选，文件名、文件夹名 |
| file_type | 文件类型 | 可选，`image, video, document, archive, software, other` |

#### 2.5.4 文件列表边界条件

1.  **文件名边界**：文件名包含 `video`，符合允许的文件名格式（仅字母数字下划线），长度 15 位 ≤ 255 字符。
2.  **文件大小边界**：文件大小 > 100MB，符合允许的文件大小（10GB）。
3.  **文件类型边界**：文件类型为 `video/mp4`，符合允许的文件类型（视频支持）。
4.  **排序边界**：排序方式为 `created_at desc`，按创建时间倒序。
5.  **分页边界**：每页显示 20 个文件，当前页为第 1 页，总页数 5 页。
6.  **文件状态边界**：文件为正常状态（非删除、非隐藏），权限足够。
7.  **文件权限边界**：用户无权限查看文件 → 403 错误。
8.  **文件识别边界**：文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值正确。
9.  **文件列表完整性边界**：文件列表完整，无遗漏文件。

#### 2.5.5 文件列表异常处理

-  **服务器异常**：服务器错误 → 返回 500 错误，记录错误日志。
-  **文件不存在异常**：文件不存在 → 返回 404 错误，提示文件不存在。
-  **文件权限不足异常**：文件权限不足 → 返回 403 错误，提示用户无权限。
-  **文件类型不支持异常**：文件类型不支持 → 返回 400 错误，提示文件类型不支持。
-  **文件内容包含敏感词异常**：文件内容包含敏感词 → 返回 400 错误，提示内容违规。

#### 2.5.6 文件列表业务规则

-  **文件列表查询** → 服务端返回文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值）。
-  **分页信息** → 服务端返回分页信息（当前页、总页数、总记录数、是否有下一页、是否有上一页）。
-  **文件列表显示** → 客户端显示文件列表（文件名、文件大小、文件类型、文件创建时间、文件更新时间、文件夹标志、文件权限、文件存储路径、文件哈希值）。

## 四、业务规则与非功能性需求

### 4.1 核心业务规则

#### 4.1.1 文件校验

| 校验项 | 规则 |
|--------|------|
| 文件名 | 仅允许字母、数字、下划线，长度 1~255 字符 |
| 文件大小 | 不超过单文件最大限制（10GB） |
| 文件类型 | 仅允许允许类型（图片、视频、文档、压缩包、软件、其他） |
| 文件内容 | 不允许包含敏感词（如 " copyrighted"） |

#### 4.1.2 上传与下载

| 业务规则 | 描述 |
|----------|------|
| 文件哈希校验 | 上传文件时，计算 MD5/SHA256，服务端查询 `file_hashes` 表，命中则秒传，未命中则上传 |
| 文件分块上传 | 文件大小超过 500MB 时，分块上传（4MB），支持断点续传 |
| 文件断点续传 | 用户网络断开，断点续传，支持 resume |
| 文件秒传 | 文件哈希值查询 `file_hashes` 表，命中则秒传 |
| 文件下载 | 支持 Range 请求、多线程下载、断点续传、文件校验 |
| 分享链接 | 生成短 ID 分享链接，支持密码保护、过期时间、访问次数控制 |
| 用户配额 | 用户初始配额 1GB，每月 1 号重置，超过配额时上传失败 |
| 文件列表 | 支持文件名、文件大小、文件类型、文件状态、文件权限、文件存储路径、文件哈希值筛选 |
| 文件夹管理 | 支持文件夹创建、重命名、移动、删除、共享 |

### 4.2 非功能性需求

#### 4.2.1 性能需求

-  **上传性能**：上传 500MB 文件，时间 ≤ 15 秒，成功率 ≥ 99%

-  **并发能力**：支持 10000 并发用户，单文件上传/下载能力 ≥ 10000/秒

#### 4.2.2 安全需求

-  **敏感词过滤**：上传文件内容需过滤敏感词
-  **权限控制**：需进行文件权限校验（文件夹权限、文件类型权限、文件敏感词权限）

## 五、系统架构与技术栈

### 5.1 系统架构

NimbusDrive 系统采用微服务架构，前端与后端分离。系统架构如下：

```
+---------------------+      +---------------------+      +---------------------+
|     Web 端          |      |     移动端          |      |     后端服务        |
|     (React)        |      |     (React Native) |      |     (Go + Gin)      |
+---------------------+      +---------------------+      +---------------------+
                      |                         |                         |
                      v                         v                         v
              +---------------------+  +---------------------+  +---------------------+
              |  API 网关 (Kong)     |  | 业务服务 (Go)        |  | 数据库 (MySQL / MinIO) |
              | 限流+认证+日志记录   |  | 文件存储、用户管理、 |  | 事务支持、索引、备份  |
              +---------------------+  +---------------------+  +---------------------+
                      |                         |                         |
                      v                         v                         v
               +---------------------+  +---------------------+  +---------------------+
               |  安全层 (JWT)        |  | 消费者服务 (Go)     |  | 容器化 (Docker/K8s)    |
               |  用户认证、权限控制   |  | 上传、下载等功能     |  | 自动扩缩容、健康检查  |
               +---------------------+  +---------------------+  +---------------------+

```

### 5.2 技术栈

-   **后端技术**：Go (Gin + sqlx + GORM)，MySQL，MinIO，Redis，Kong，JWT
-   **前端技术**：React (Vite + Ant Design + Zustand + TanStack Query)，React Native (Expo)，Axios，React Router
-   **部署架构**：Docker + Kubernetes + Nginx + Kong API 网关
-   **协议支持**：RESTful + WebDAV（通过 API 网关代理）+ S3 + FTP（已弃用）
-   **开源协议**：Apache 2.0
